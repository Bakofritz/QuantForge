## 2. Engineering work
### Deterministic trade-path exposure
The deterministic EMA backtest now retains the completed-trade PnL sequence as research output. This is not a new data source; it exposes observations already generated by the deterministic backtest so statistical resampling can operate on them without reconstructing or mutating market data.

### Monte Carlo/bootstrap analyzer
Added `DeterministicMonteCarloAnalyzer` and contracts for:
- iteration count;
- trades per iteration;
- observed net PnL;
- mean and median resampled net PnL;
- 5th/95th percentile net PnL;
- mean and 95th percentile maximum drawdown;
- probability of non-positive resampled PnL;
- probability of resampled drawdown at least the observed baseline drawdown;
- deterministic seed fingerprint;
- report fingerprint.

The resampling method is bootstrap-with-replacement over the observed completed-trade PnL sequence. A deterministic custom PRNG is used so the same seed and inputs reproduce the same sample path.

### Native runtime integration
`ResearchRuntime.RunMonteCarloAsync` now places Monte Carlo behind:
- job lease acquisition;
- canonical data validation;
- dataset identity validation;
- deterministic configuration fingerprint;
- durable job/checkpoint record;
- evidence record;
- append-only completion event;
- lease release.

## 3. Statistical boundary
Monte Carlo/bootstrap here is a resampling analysis of observed backtest trade outcomes. It does not simulate new market paths, discover future information, or establish a probability of future live performance.

The probability fields are probabilities within the generated bootstrap sample under the declared resampling method. They must not be presented as empirical future-market probabilities.

## 4. Data-fidelity boundary
The source backtest remains OHLCV bar-driven. Bootstrap resampling cannot create tick ordering, bid/ask, spread, or intrabar sequencing. Those require corresponding source/event data and an appropriate execution model.

## 5. Safety boundary
No live trading, live order placement, arbitrary code execution, application-setting mutation, manifest bypass, or canonical-data mutation was introduced.

## 7. Known limitations
- Bootstrap operates on trade PnL observations rather than raw market-event resimulation.
- Trade dependence, regime dependence, and serial correlation are not modeled by the simple IID bootstrap method.
- No block bootstrap/stationary bootstrap is included yet.
- Monte Carlo execution is checkpoint-attached but not yet chunk-resumable at an iteration cursor.
- Native runtime/device validation remains pending.
